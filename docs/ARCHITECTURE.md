# Архітектура

Табло — це звичайний сайт (PWA) на чистому JavaScript без фреймворків і без збирання,
плюс невеликий Node-сервер, який роздає цей сайт і синхронізує матч між пристроями.

```
volleyball_scoreboard/
├── public/      сайт: усе, що отримує браузер
├── server/      Node-сервер: роздає public/ + WebSocket /ws
├── scripts/     службові скрипти (перевірка перед деплоєм)
├── tests/       автотести (node:test + jsdom)
└── docs/        інструкція для суддів, тестування, ця архітектура
```

## Сторінки

Усі сторінки лежать у корені `public/`, тож адреси не залежать від внутрішньої
структури папок: посилання на кшталт `…/live.html?room=ABC234`, вже додані в Prism Live,
працюють і далі.

| Сторінка | Для кого | Скрипт | Стилі |
|---|---|---|---|
| `index.html` | суддя: пульт з усіма правилами, налаштуваннями, протоколом | `js/pages/pult.js` | `css/pages/pult.css` |
| `display.html` | глядачі: велике табло на ТБ чи проєкторі (арена / смуга) | `js/pages/display.js` | `css/pages/display.css` |
| `live.html` | стрім (Prism Live) і телефони глядачів: маленьке міні-табло | `js/pages/live.js` | `css/pages/live.css` |
| `mini.html` | суддя: міні-табло + кнопки в окремому маленькому вікні | `js/pages/mini.js` | `css/pages/mini.css` |

## Шари JavaScript

Залежності йдуть лише згори вниз: сторінки → спільні модулі → ядро.

```
js/pages/    pult.js   display.js   live.js   mini.js        ← екран, жести, DOM
                │          │          │         │
js/shared/   ui-common · scorebug · remote · link · archive · feed · sounds  ← спільні модулі
                │
js/core/     match.js · palettes.js                           ← ядро без DOM
```

- **`js/core/`** — чиста логіка, жодного DOM. Ті самі файли працюють у браузері
  (`window.Match`, `window.Palettes`) і в Node (`require`), тому правила тестуються без браузера.
  - `match.js` — правила волейболу. Матч — це список подій (`point`, `timeout`, `swap`,
    `serve`, `sub`, `card`), а стан щоразу рахується з нуля функцією `reduce`.
    Звідси безкоштовно: скасування, повтор, протокол, статистика, синхронізація.
    Кожна подія має `id`, матч — `mid` і `created`; скасоване й зняте записується в `removed`.
    `merge(local, incoming)` зливає два пульти одного матчу: події обох без видалених,
    по черзі за часом; назви й правила — від новішого `metaAt`; інший `mid` — виграє новіший
    матч; стан старої версії (v1, без `id`) не зливається — діє як прийшов. `clock()` не
    відстає від найпізнішого баченого часу, тож годинники телефонів можуть розходитись.
    Тут же пауза після кінця матчу (`finalHoldLeft`, `shownPoints`, 10 с): табло ще
    показують рахунок останнього сету, потім фінал.
  - `palettes.js` — кольори: готові палітри команд, палітра вибору (90 кольорів, `SWATCH_ROWS`),
    свої кольори команд і таблиці (`apply`, `applyBoard`), підбір читабельного тексту (`ink`).
    Типові кольори таблиці (`BOARD_DEFAULT`) повторюють `css/theme.css`.
- **`js/shared/`** — те, що потрібно кільком сторінкам:
  - `ui-common.js` — формат часу, кружечки сетів, Wake Lock, реєстрація офлайн-кешу,
    вибір і показ емблем ліги (`logoPick`, `paintLogos`).
  - `scorebug.js` — малює таблицю міні-табла (спільна для `live` і `mini`, стилі — `css/scorebug.css`).
  - `remote.js` — WebSocket до сервера, перепідключення, коди кімнат і ключі судді.
  - `link.js` — «Посилання на матч» без DOM: збереження (`volleyball:link`), адреса пульта
    другого судді, адреси міні-табла, відлік часу без звʼязку (`lossTracker`), перевірка
    `/healthz` і причини збою (`reasons`). `pult.js` лише малює й тримає зʼєднання;
    тести — `tests/link.test.js`, без браузера.
  - `archive.js` — архів матчів на цьому пристрої (`volleyball:archive`, до 30): матч потрапляє
    туди, коли закінчився або коли суддя почав новий; той самий `mid` оновлюється, не дублюється;
    брак місця — викидає найстаріші. Пульт показує список, протокол і CSV архівного матчу.
  - `feed.js` — звідки табло бере рахунок: цей пристрій або кімната на сервері.
  - `sounds.js` — звуки великого табло (Web Audio).
- **`js/pages/`** — по одному файлу на сторінку. Тут лише робота з екраном.

Кожен модуль — самодостатній IIFE (UMD-обгортка), який кладе одне імʼя в `window`.
Порядок `<script>` у сторінках — від ядра до сторінки (перевіряє `tests/markup.test.js`).

## Як рухається рахунок

```
                 той самий пристрій                        інші пристрої
pult.js / mini.js ──localStorage "volleyball:match"──┐
                 └─BroadcastChannel "volleyball"─────┤
                                                     ├─▶ display.js, live.js  (feed.js)
                 └─remote.js ─▶ server/ (кімната ABC234) ─▶ live.js, display.js, pult.js 2-го судді
```

- Пульт зберігає матч у `localStorage` і розсилає його через `BroadcastChannel`:
  табло в сусідньому вікні оновлюється миттєво, навіть без інтернету.
- «Посилання на матч» — кімната на сервері. Пульт надсилає туди свій стан; сервер
  **зливає** його з тим, що має (`Match.merge`), роздає глядачам (лише читання) і пультам
  з тим самим ключем судді, а відправнику повертає злите, якщо там було щось нове.
  Пульт, отримавши стан, теж зливає його зі своїм і, якщо мав своє, віддає злите назад.
  Однаковий зміст (`Match.syncKey`) — нічого не пересилається, тож пінг-понгу немає.
- Після перепідключення свій матч надсилає кожен пульт; другий суддя — лише якщо вже
  бачив саме цей матч (`link.mid`): свіжий пульт судді бере матч із сервера як є.
- Налаштування показу (палітра, свої кольори, подача, звук, тайм-аут, розмір міні-табла, емблеми)
  ідуть тим самим шляхом як `prefs`. Сервер пропускає лише дозволені поля (`PREF_KEYS`
  у `server/server.js`).
- Вигляд міні-табла (макет, смуга з назвою, «на весь віджет») живе в самій адресі
  `live.html?…`, тож одна кімната може виглядати по-різному в різних місцях.

## Стилі

- `css/theme.css` — токени (кольори, шрифти). Єдине місце, де вони оголошені.
- `css/scorebug.css` — таблиця міні-табла, спільна для `live` і `mini`.
- `css/pages/*.css` — стилі однієї сторінки.

## Ресурси

- `assets/fonts/` — Barlow Condensed (цифри, латиниця) і Roboto Condensed (кирилиця), OFL.
- `assets/icons/` — іконки застосунку для `manifest.webmanifest`.
- `assets/logos/` — емблеми Ужгородської волейбольної ліги: `uvl-new.webp` (синьо-жовта),
  `uvl-old.webp` (попередня, із замком).

## Офлайн-кеш

`public/sw.js` лежить у корені сайту, щоб діяти на всі сторінки. Список `SHELL` у ньому —
це **усі** файли `public/`. `npm run build` (`scripts/build.js`) падає, якщо список і папка
розійшлися, а Render і CI запускають його перед кожним деплоєм.

Версію `CACHE` у `public/sw.js` `npm run build` рахує сама: це хеш усіх файлів `SHELL` і самого
`sw.js` (`volley-score-<10 hex>`). Змінився хоч байт — нова версія, і встановлені застосунки
оновляться. Вписує її прапорець `--stamp` (його передає `npm run build`); `node scripts/build.js`
без прапорця лише перевіряє. На Pages після `pages-config.js` версія перераховується ще раз.

## Хостинг: Render і GitHub Pages

| | Render (Web Service) | GitHub Pages |
|---|---|---|
| що віддає | `public/` + сервер посилань (`server/`) | лише `public/` |
| посилання на матч | той самий сайт | через сервер на Render (`SYNC_SERVER`) |
| деплой | `render.yaml`, пуш у `main` | `.github/workflows/pages.yml`, пуш у `main` |

Адресу сервера посилань задає `public/js/config.js` (`syncServer`), він підключається першим
на кожній сторінці. У репозиторії там порожньо — тоді сервер той самий сайт (Render).
Під час деплою на Pages `scripts/pages-config.js` вписує туди змінну `SYNC_SERVER`.
Логіку вибору сервера містить `Remote.defaultServer` (`js/shared/remote.js`): `syncServer` →
той самий сайт → на `*.github.io` без налаштування сервера немає. Усі адреси на сторінках
відносні (`./…`), тож сайт працює й у підпапці `github.io/<репозиторій>/`.

## Сервер

`server/server.js` — один процес на Render:

- роздає `public/` як є (сторінки, скрипти й стилі — `no-cache`, решта — на годину);
- `GET /healthz` — перевірка, що це саме сервер, а не Static Site (з `Access-Control-Allow-Origin: *`,
  щоб пульт із GitHub Pages міг перевірити сервер на Render);
- `WS /ws` — кімнати матчів: перший пульт закріплює хеш ключа судді, глядачі лише читають,
  кімната з пультом без підключень живе добу; кімната, яку створив лише глядач, зникає,
  щойно вийде останній глядач;
- доказ власності кімнати: у `hello` пульт отримує `proof` = «час.HMAC(ROOM_SECRET, код:хеш ключа:час)»
  і зберігає його в посиланні (`volleyball:link`). Після перезапуску сервера пульт показує доказ,
  і кімната повертається йому, навіть якщо її встиг зайняти хтось інший: давніший доказ виграє,
  самозванця відключає (4003). `ROOM_SECRET` задає Render (`render.yaml`, `generateValue`);
  без нього секрет випадковий на кожен запуск — тоді все як раніше, лише без цього захисту;
- кожен стан від пульта проходить `Match.validate` (`js/core/match.js`) — зіпсована подія
  не дійде до глядачів. У браузері `Match.deserialize` поблажливий: викидає лише зіпсоване;
- проксі Render губить коди закриття WebSocket (браузер бачить лише 1006 через ~20 с), тому
  відмову сервер спершу шле повідомленням `{type:"error", code}`, а клієнт, виходячи, — `{type:"bye"}`;
  `Remote.connect` розуміє обидва, на код закриття не покладаємось;
- ліміти на IP (`MAX_CONN_PER_IP`, `MAX_NEW_ROOMS_PER_IP` за хвилину), відмова — код 1013,
  клієнт перепідключається сам. На Render адреса — останній запис `X-Forwarded-For`.

Запуск: `npm start` (і локально, і на Render).

## Тести

`tests/*.test.js` звертаються до файлів короткими іменами (`read("live.html")`,
`load("match.js")`); де вони лежать насправді, знає лише `tests/helpers/site.js`.
Переносите файл — оновіть одне місце там.

`tests/e2e/` — Playwright (`npm run e2e`): справжній Chromium і справжній сервер, що вміє
перезапускатися на тому ж порту (`tests/e2e/helpers.js`). `npm test` їх не запускає;
Render ставить лише залежності без dev, тож Playwright туди не потрапляє.

## Куди класти нове

| Що | Куди |
|---|---|
| нове правило гри, підрахунок | `js/core/match.js` (+ тест у `tests/match.test.js`) |
| код, потрібний двом і більше сторінкам | `js/shared/` |
| логіка однієї сторінки | `js/pages/<сторінка>.js` |
| стиль однієї сторінки | `css/pages/<сторінка>.css` |
| спільний колір чи шрифт | `css/theme.css` |
| картинка, шрифт, іконка | `public/assets/…` |
| новий файл у `public/` | додайте його в `SHELL` у `public/sw.js` (`CACHE` оновить `npm run build`) |
| нове налаштування, яке має дійти до табло | `PREF_KEYS` у `server/server.js` |
